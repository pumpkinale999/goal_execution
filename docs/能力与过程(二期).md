## 1. 需求

### 1.1 一句话

> **在单机、单用户、简单 MCP Tool 场景下，由 Master 编排五个 Forge Expert（architect / engineer / tester / integrator / analyzer），在 master profile workspace 内协作完成 Spec → 实现 → 集成测试 → Hermes 发布；执行链 block/fail 时由 analyzer 产出 RCA 并从对应步骤重跑；各 Agent 具备结构化输入/输出及 happy / bad path。**

### 1.2 对齐 [能力与过程 §3](./能力与过程.md#三domain-tool-全生命周期)

| §3 阶段 | 二期 Forge 对应 | 说明 |
| --- | --- | --- |
| **3.1 规划** | **mcp-architect** · `FORGE-SPEC.yaml` | Spec = 规划 + 技术设计 + 测试要求 + 步骤拆解 |
| **3.2 实现** | **mcp-engineer** · `repo/` | FastMCP + 单元测试；**非** slug Git Python |
| **3.3 测评** | **mcp-tester** · `test-report/` | 集成 / 协议 smoke；L2 REG 场景 **二期不做** |
| **3.4 部署** | **mcp-integrator** · platform MCP registry | `register_server` + `hermes mcp test --from-registry` = 部署完成 |
| **3.5 配置落盘** | integrator + [一期](./能力与过程(一期).md) 消费侧 | Forge 写 **`platform-mcp-servers.yaml`**；slug overlay 展开归一期 |
| **（Forge 仲裁）** | **mcp-analyzer** · `RCA.json` | 执行链失败根因；**不**替代 §3.1–3.4 角色 |

**Normative · Forge 与 catalog**：单人 MVP 下 Forge integrator 完成即视为 [§3.2](./能力与过程.md#32-实现) 本机可用；**附录 C catalog 登记**与 slug overlay 启用仍按 [附录 C.5 过渡](./能力与过程.md#c5-过渡行为t3-前--normative) 与 [一期](./能力与过程(一期).md)（**不**作为 Forge Done 前置）。

### 1.3 治理原则（normative）

| 原则 | 说明 |
| --- | --- |
| **申请构建** | 用户在 IM 提出「构建 MCP Tool」即开工入口；**不**叠加多层表单审批 |
| **Master = 对用户通道 + 编排** | **所有** Forge Agent 需用户输入时 **经 Master** 转发；Master **不写 Spec** |
| **Spec = architect** | `FORGE-SPEC.yaml` 由 **mcp-architect** 起草；确认 Spec 经 Master 问用户 |
| **RCA = analyzer** | 执行 Agent block/fail → Master 派 **mcp-analyzer** → `RCA.json` · `restart_from` |
| **不替 Agent 代言** | analyzer **不**代替 engineer/tester/integrator 向用户传话；**谁 block，谁经 Master 问**（Spec 澄清除外，属 architect 本职） |
| **结构化 I/O** | 各 Agent 机读 **卡 body 输入 + workspace 文件 + complete/block metadata**；见 [§2.11](#211-agent-io-契约normative) |
| **Skill-first** | 多步 MCP 供给 playbook 细则在 **`mcp-supply-greenfield`** / **`mcp-supply-iterate`** skill；Master SOUL **不**重复步骤；未命中 playbook → 通用 Kanban（`skstudio-consensus-plan`）；**平台 L5**（`kanban_playbook_registry`）校验 registered playbook，非仅靠 SOUL 纪律 |
| **Registry 直写** | integrator 经 **`platform_mcp_registry.register_server()`** 写 **`platform_registry_path`**；**禁止** patch master `config.yaml` · `mcp_servers` |
| **单人 MVP** | 暂不多用户协作；artifact 真源 = master workspace，**不依赖 Git** |

### 1.4 用户故事（normative）

| ID | 作为 | 我要 | 以便 |
| --- | --- | --- | --- |
| **F1** | 用户 | 描述要什么 MCP Tool 后，Agent 协作完成实现并接到 Hermes | 对话里能用到新 tools |

| **F3** | 用户 | 执行链失败时 **不用自己判** Spec/代码/配置问题 | analyzer 给出根因与重跑步骤 |

| **F8** | Master | 见 block/fail 派 analyzer，按 `restart_from` 重派 | RCA 重派 **不需用户判根因**（env / escalate 除外） |

## 2. 技术设计

### 2.1 架构

```text
用户 IM
    ↓
Master（编排 · 对用户唯一 IM 出口 · skill-first 选 playbook）
    ↓ skills_list / skill_view（greenfield 8 步 · iterate 9 步）
    ↓ plan_put → authorize → materialize（执行 + 审查交错）
┌──────────────────────────────────────────────────────────────┐
│  profiles/master/workspace/mcp-forge/<server-name>/          │
│    FORGE-SPEC.yaml · spec-confirmed.json · repo/ ·           │
│    test-report/ · integration-pack/ · reviews/*.json         │
└──────────────────────────────────────────────────────────────┘
    ↓ iterate 首步：analyzer(assess) → assess-report.json
architect → analyzer(review) → engineer → analyzer(review) → … → integrator → analyzer(review)
    ↑________________________ retry（每执行步最多 1 次）______________|
    └─ escalate → Master 问用户

共享根下 `platform-mcp-servers.yaml` · servers.<name>（task `[kanban-paths]` · `platform_registry_path`）
    ↓ hermes mcp test --from-registry · slug sync 展开 mcp_servers
agent / slug profile 可调用 mcp_<name>_*
```

**Normative · 注册真源（方案 B）**：integrator **禁止** patch `profiles/master/config.yaml` · `mcp_servers`；master profile **`mcp_servers: {}` 为预期**。iterate **`forge_assess`** 读 registry + artifact 树，**不得**因 master 空而报「注册丢失」。见 [§2.11.5 assess](#2515-mcp-analyzer--assess--review)。

> **v1.2.9（2026-07-10 · PR-TB-5 已实现）**：Forge IM 编排入口在 **Tool Builder Bot**（`tool-builder` profile）；`artifact_root` 默认根为 `profiles/tool-builder/workspace/mcp-forge/`；integrator **`FORGE_REGISTRY_MODE=staging`** 至 Inbox approve 写 live。

**与 Kanban 关系**：

- **与三期 consensus 一致**：`kanban_workflow_open` → **`plan_put`**（`meta.playbook_id=mcp-forge` · **8 步**：4 执行 + 4 `mcp-analyzer` 审查）→ 用户同意 → **`authorize`** → **`materialize`** 一次建齐卡；workflow **phase=executing** 与卡状态同步。
- **统一步骤闭包（§2.6）**：每执行步后 **必**经 plan 内审查步；**唯一后续动作** = `pass` / `retry`（每执行步最多 1 次）/ `escalate`；**禁止** ad-hoc 派 analyzer、**禁止** executing 中 replan。
- **派活单位** = Kanban 卡；**磁盘真源** = **tool-builder** workspace 子目录（`profiles/tool-builder/workspace/mcp-forge/<server-name>/` · **非** master · **非**默认 `kanban/workspaces/t_xxx/`）
- 卡 `body` **必须**含 `artifact_root` 与 `mode`（见 §2.8、§2.11）；下游由 **parents** 自动串链（含审查 pass 后解锁）。

### 2.2 角色（normative）

| Profile | 职责 | 对用户（经 Master） | 主要产出 |
| --- | --- | --- | --- |
| **master** | 编排、转发、重派 | ✅ 唯一 IM 出口 | Kanban 卡、`.forge-state.json`（可选）；读 supply playbook skill |
| **mcp-architect** | **Spec** | Spec 确认/澄清 | `FORGE-SPEC.yaml`、`spec-confirmed.json` |
| **mcp-engineer** | 实现 + 单元测试 | 本步 block 时 | `repo/`、`engineer-report.json`（可选） |
| **mcp-tester** | 集成 / 协议测试 | 本步 block 时 | `test-report/summary.json` |
| **mcp-integrator** | Hermes 发布 | 本步 block 时（如 env） | `integration-pack/`、**platform registry** 条目 |
| **mcp-analyzer** | **assess**（iterate 首步）+ **每步审查**（plan 内） | **默认不对用户**（`escalate` 交 Master） | `reviews/assess-report.json`、`reviews/*-review.json` |

**明确不复用**：[intel](./hermes-profiles/intel/SOUL.md) / [coder](./hermes-profiles/coder/SOUL.md) / [office](./hermes-profiles/office/SOUL.md)。

**Master 不做**：写 Spec、做审查、替 Agent 向用户提问（Spec 意图确认除外 · 仅转发）。

**mcp-analyzer 不做**：写/改 Spec、写 `repo/`、改 `mcp_servers`、`kanban_create`、对用户提问（`escalate` 时只写 review JSON，由 Master 问用户）。

**mcp-architect 不做**：写业务代码、跑集成测试、改 `mcp_servers`、做审查、代替其他 Agent 传话。

### 2.3 Workspace 布局（normative）

**根路径（normative · v1.2.9）**（`<shared_root>` = `HERMES_SHARED_ROOT` 或 `~/.hermes`）：

```text
<shared_root>/profiles/tool-builder/workspace/mcp-forge/<server-name>/
├── FORGE-SPEC.yaml         # architect
├── spec-confirmed.json     # architect · 用户确认（经 Master）
├── repo/                   # engineer
├── engineer-report.json    # engineer · 可选
├── test-report/            # tester
│   ├── summary.json
│   └── ...
├── integration-pack/       # integrator
│   ├── mcp_servers.fragment.yaml
│   └── verify.log
├── reviews/                # analyzer · assess + 每步审查
│   ├── assess-report.json  # iterate 首步 · forge_assess
│   ├── spec-review.json
│   ├── implement-review.json
│   ├── test-review.json
│   └── integrate-review.json
└── .forge-state.json       # 可选 · Master 写 retry 计数
```

**`<server-name>` 规则**：

- 与 **platform registry** server id 一致；Hermes 注册 tool 时归一化为 `_`；前缀 `mcp_<server_name>_*`

**Normative · 路径优先级**：

- 卡 `body.artifact_root` **优先于** Kanban 默认卡 workspace（`kanban/workspaces/t_xxx/`）
- Forge 五 Expert **读写**仅限 `artifact_root` 及其子路径；**禁止**默认写入 `t_xxx/`
- `terminal.cwd` 应指向 `artifact_root` 或 `repo/`（integrator 见 §2.7.1）

**Normative · 并行 Forge 隔离**：

- 每个 `server_name` 对应 **独立** `artifact_root` 与可选 `.forge-state.json`；Master 建卡时 **必须**带 `server_name` + `artifact_root`，**禁止**混用路径
- 同一时刻多个 Forge 并行时，Kanban 卡以 `server_name` 区分；Master 读 metadata / RCA 时 **须**核对 `server_name` 与目录一致

### 2.4 FORGE-SPEC.yaml（mcp-architect · normative）

Spec 是 Forge **唯一契约**；engineer / tester / integrator / analyzer **只读**。

**仅 architect 可改 Spec**；`restart_from: spec` 时 architect 修订后 **须**再经 Master 请用户确认（递增 `spec_version`）。

**必填章节**：见 [附录 A](#附录-a-forge-spec-最小示例)。

**确认门禁**：`spec-confirmed.json` · `confirmed: true` 且 `spec_version` 与 `FORGE-SPEC.yaml` · `meta.version` 一致后，**forge_review_spec** pass 方可解锁 engineer。

**Normative · Spec 修订**（审查 `verdict: retry` 指向 spec 或用户要求改 Spec）：

1. architect 更新 `FORGE-SPEC.yaml` · `meta.version`（递增整数）
2. **须**将 `spec-confirmed.json` 置为 `confirmed: false`（或删除后重建），直至 Master 转发用户再次确认
3. 再确认后写 `confirmed: true` 且 **`spec_version` = 新 `meta.version`**
4. Master **仅**在二者一致后派 engineer；**禁止** engineer 在旧确认下对新 Spec 开工

### 2.5 主流水线（normative · 8 步 plan）

```text
① 用户：申请构建 MCP Tool（server_name + 用途）
② Master：plan_put（8 步）→ 用户「同意，按方案建卡」→ authorize → materialize
③ forge_spec · mcp-architect → block(awaiting_spec_confirmation) → Master ↔ 用户 → complete
④ forge_review_spec · mcp-analyzer → reviews/spec-review.json · verdict
⑤ forge_implement · mcp-engineer → repo/
⑥ forge_review_implement · mcp-analyzer → reviews/implement-review.json
⑦ forge_test · mcp-tester → test-report/
⑧ forge_review_test · mcp-analyzer → reviews/test-review.json
⑨ forge_integrate · mcp-integrator → integration-pack + platform registry
⑩ forge_review_integrate · mcp-analyzer → reviews/integrate-review.json
⑪ Done：末步 review pass + integrator I1–I5 + Master gateway restart
```

**Kanban parents 自动串链**；Master **勿**手动 `kanban_create` 派下游。

**Spec 人环（§2.11.1）**：architect `awaiting_spec_confirmation` → Master 转发 · **不**走审查 retry。

### 2.6 统一步骤闭包（mcp-analyzer · review · normative）

**原则**：失败与「质量不高」走 **同一机制**；**无**双轨 replan / ad-hoc analyzer。

**每执行步后**：plan 内 **审查步**（`kind: review` · `mode: review`）读取上游产出，写 `reviews/<step>-review.json`。

**流程**：

```text
执行步 complete 或 block
    → 审查步（plan 内 mcp-analyzer）读证据 → reviews/*.json
    → verdict: pass | retry | escalate
    → pass：Kanban parents 解锁下游
    → retry：Master 对 reviewed_step_key 对应卡 retry 一次（§2.6.1）
    → escalate：Master IM 问用户
```

**reviews/*.json 字段（normative）**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `server_name` | string | 与目录名一致 |
| `reviewed_step_key` | string | 如 `forge_implement` |
| `reviewed_task_id` | string | 被审 Kanban task id |
| `reviewed_forge_mode` | enum | `spec` \| `implement` \| `test` \| `integrate` |
| `verdict` | enum | **`pass`** \| **`retry`** \| **`escalate`** |
| `quality` | enum | 可选 · `ok` \| `low` |
| `summary` | string | 一句话 |
| `findings[]` | string[] | 可执行建议 |
| `evidence[]` | string[] | 绝对路径 |
| `escalate` | bool | 与 `verdict: escalate` 一致 |

**审查 complete metadata** 须含：`forge_step: analyzer_review`、`verdict`、`artifact_path` → 对应 review JSON。

**env shortcut**：integrator `block_reason: env_missing` → Master 请用户配 `.env` → `kanban_unblock` integrator；**可**在审查前做人环，**不**替代末步 review。

#### 2.6.1 Retry 纪律（normative）

| 规则 | 说明 |
| --- | --- |
| 每 **执行步** 每个 review 周期 **最多 1 次** retry | Master 维护 `.forge-state.json` · `retry_count`（按 `reviewed_step_key`） |
| 第二次仍 `retry` 或 `escalate: true` | Master **IM 问用户**，不自动再跑 |
| retry 动作 | **`kanban_unblock`**（blocked）或 skstudio **重试这一步** / 后续 `kanban_workflow_retry_step`（failed/done 重跑） |
| **禁止** | executing 中 `plan_put` v2、ad-hoc `kanban_create` 派 mcp-* |

**Legacy**：`RCA.json` / `mode: analyze` 仅作历史参考；**新 Forge 只用 plan 内 `mode: review`**。

### 2.7 integrator 发布 DoD

integrator **`kanban_complete` 前**须全部满足：

| # | 检查 | 验证方式 |
| --- | --- | --- |
| I1 | `test-report/summary.json` · `verdict: pass` | read_file |
| I2 | registry 中 `<server_name>` 可启动 | §2.7.1 · `hermes mcp test <server_name> --from-registry` |
| I3 | 所需 env 在 `profiles/master/.env` 已设置 | `hermes mcp test <server_name> --from-registry` 不红；缺则 integrator `block_reason: env_missing` |
| I4 | worker/lab profile sync 后 schema 含 Spec 各 tool 的 `mcp_<server>_*` | slug sync-runtime 后 `discover_mcp_tools` 或 `--from-registry` test pass（**不**要求 master Gateway 加载 `mcp_servers`） |
| I5 | `kanban_complete.metadata.registered_tools[]` | Master 汇报 |

**Normative**：二期 **不**要求 catalog YAML commit、**不**要求 slug overlay 已启用。

#### 2.7.1 integrator 写 platform MCP registry（normative · 方案 B）

integrator 跑在 **`mcp-integrator` profile**，目标 **`platform_registry_path`**（task `[kanban-paths]`）。integrator 通过 **`platform_mcp_registry.register_server()`** 写入 registry。

**禁止** patch `profiles/master/config.yaml` · `mcp_servers`。

**Happy path**：

1. 写 `integration-pack/mcp_servers.fragment.yaml`（供 diff · **非**运行时真源）
2. **`register_server()`** 写入 **`platform_registry_path`**
3. `hermes mcp test <server_name> --from-registry` → 写 `integration-pack/verify.log`
4. **禁止** integrator 写 `profiles/master/.env`（用户经 Master 配 key）
5. **`kanban_complete`** · `registered_tools[]` · `gateway_restart_required: true`

**迁移**：现网 master `mcp_servers` → [migrate-master-mcp-to-registry.sh](./hermes-profiles/scripts/migrate-master-mcp-to-registry.sh)（与 integrator 改版同发版）。

#### 2.7.2 Gateway restart（normative）

| 角色 | 职责 |
| --- | --- |
| **integrator** | registry 登记 + `hermes mcp test --from-registry` 通过后，在 `kanban_complete.metadata` 设 `gateway_restart_required: true` |
| **Master** | 见 integrator complete 且 I2 已满足 → 执行 master Gateway restart → 再验 I4；**或** 在 IM 请用户重启后重派 integrator 仅做 I4 |

**Normative · restart CLI（master profile）**：`hermes -p master gateway restart`（或等价 `hermes gateway restart` 且当前 profile 为 master）。integrator **不**执行此命令。

integrator profile **不起** skstudio Gateway；**不**假定 integrator 进程内 `discover_mcp_tools` 已生效，以 **Master 侧 master profile** 重启后 schema 为准。

### 2.11 Agent I/O 契约（normative）

Forge Agent 之间 **只**通过 **卡 body + workspace 文件 + complete/block metadata** 协作。禁止仅自然语言 complete。

**Normative · metadata 载体**：下列字段写入 Hermes 工具 **`kanban_complete` / `kanban_block` 的 `metadata` 对象**（与 [coder SOUL](./hermes-profiles/coder/SOUL.md) 一致：工具参数 `summary` **与** `metadata.summary` **均须**填写；Forge 扩展字段放 `metadata` 内）。

**Forge · 推荐调用形状**（tester happy path 示例）：

```python
kanban_complete(
    summary="集成测试全过，verdict pass。",
    metadata={
        "summary": "集成测试全过，verdict pass。",
        "forge_step": "tester",
        "verdict": "pass",
        "artifact_path": "/abs/.../mcp-forge/httpbin/test-report/summary.json",

```

```python
kanban_block(
    summary="pytest 3 failed，无法交付 repo。",
    metadata={
        "summary": "pytest 3 failed，无法交付 repo。",
        "forge_step": "engineer",
        "block_reason": "implementation_failed",
        "failed_step": "engineer",
        "phenomenon": "pytest 3 failed",
        "evidence_paths": ["/abs/.../repo/.pytest.log"],
    },
)
```

**约定**：

- **Happy path** → `kanban_complete` + 必填 metadata + 产出文件
- **Bad path** → `kanban_block` + 必填 metadata（执行链 bad → 触发 analyzer）
- metadata 字段与 JSON 文件 **须**符合下列 schema；Master SOUL **应**读 `restart_from` / `verdict` / `confirmed`

#### 2.11.0 Master（编排 · 非 Forge worker）

Master **不**走 `kanban_complete` 交付 Forge artifact；其结构化 I/O 如下：

| --- | --- |

##### assess（`forge_mode: assess` · iterate 首步）

| | 内容 |
| --- | --- |
| **输入 body** | `mode: assess`, `artifact_root`, `server_name`, `forge_spec` 路径 |

| **Happy 文件** | `reviews/assess-report.json` |
| **Happy complete metadata** | `forge_step: assess`, `restart_from`, `artifact_path` |
| **Bad block** | `block_reason: insufficient_evidence` |
| **Bad 下一步** | Master 补证据或 escalate |

**`assess-report.json`（normative · 路径 `{artifact_root}/reviews/assess-report.json`）**：

```json
{
  "server_name": "httpbin",
  "registration": {
    "platform_registry": "present",
    "platform_registry_path": "/abs/.../platform-mcp-servers.yaml",
    "master_mcp_servers": "empty_expected"
  },
  "artifact_tree": {
    "forge_spec": true,
    "spec_confirmed": true,
    "repo": true,
    "test_report": true,
    "integration_pack": false
  },
  "health": {
    "pytest": "pass",
    "test_report_verdict": "pass"
  },
  "restart_from": "none",
  "summary": "代码与测试健康；platform registry 已含 httpbin；master mcp_servers 空为预期。",
  "evidence": ["/abs/.../FORGE-SPEC.yaml", "/abs/.../platform-mcp-servers.yaml"]
}
```

**枚举（硬约束）**

| 字段 | 允许值 |
| --- | --- |
| `registration.platform_registry` | `present` \| `absent` |
| `registration.master_mcp_servers` | `empty_expected` \| `has_entry_for_server` \| `has_unrelated_entries` |
| `restart_from` | `none` \| `spec` \| `engineer` \| `tester` \| `integrator` |
| `evidence` | 非空字符串数组 |

**禁止语义（normative · M1b lint enforce）**

- `master_mcp_servers: empty_expected` **不得**在 summary 中表述为「注册丢失 / 注册态已丢失 / master config.yaml 注册缺失」
- `platform_registry: present` 时 **`restart_from: integrator` 仅当** `test-report/summary.json` 存在且 `verdict: pass` **且** 业务需要 **重新登记**（registry 条目损坏或与 repo 不一致）— 单纯 master 空 **禁止** 作为 integrator 理由
- httpbin 类 **healthy + registry present** → 默认 `restart_from: none` 或 `spec`（仅 Spec 增量）

**`restart_from` 决策表（normative）**

| platform_registry | artifact / 测试 | 建议 restart_from |
| --- | --- | --- |
| absent | test pass + repo 齐 | `integrator` |
| absent | repo/spec 缺 | `spec` 或 `engineer` |
| present | 测试 fail | `engineer` 或 `tester` |
| present | 全健康 | **`none`**（或 `spec` 若仅改 Spec） |
| any | 仅因 master `mcp_servers` 空 | **禁止** `integrator` |

与 [`kanban_plan_contract.py`](../../hermes-agent/hermes_cli/kanban_plan_contract.py) · `forge_assess` step 描述一致。

## 附录 A · FORGE-SPEC 最小示例

```yaml
meta:
  server_name: httpbin
  label: HTTPBin GET
  risk: normal
  version: 1

requirements:
  summary: 只读调用 httpbin.org/get
  tools_p0: [http_get]
  non_goals: [POST, auth]

design:
  api_base: https://httpbin.org
  env: {}

tools:
  - name: http_get
    description: 调用 GET /get；无 URL 参数时用默认
    params:
      query: { type: string, optional: true }

testing:
  unit:
    - domain 层 mock HTTP，断言 200
  integration:
    - id: INT-01
      tool: http_get
      valid: { query: "forge=1" }
    - id: INT-02
      tool: http_get
      invalid: { query: "" }
      expect_error: true
  protocol:
    - fastmcp inspect
    - fastmcp call http_get

steps:
  - engineer: scaffold FastMCP + pytest
  - tester: integration + protocol
  - integrator: register_server + hermes mcp test --from-registry

hermes:
  # integrator 意图：写入 platform registry 的 command/args（cwd_ref 仅 Spec 意图）
  mcp_servers:
    httpbin:
      command: uv
      args: [run, python, -m, src.httpbin_mcp.server]
      cwd_ref: repo/
```

**Normative · `cwd_ref`**：appendix 示意；integrator 写入 **platform registry** 时 **须**将启动路径解析为 **绝对路径**（指向 `artifact_root/repo/…`），与 [intel config.overlay](./hermes-profiles/intel/config.overlay.md) 同级写法。**Spec 段为 integrator 意图，非 master profile 落盘。**

## 附录 B · artifact JSON 字段速查

| 文件 | 必填字段 | 门禁 |
| --- | --- | --- |
| `assess-report.json` | `server_name`, `registration`, `restart_from`, `summary`, `evidence` | iterate 首步；§2.11.5 assess |
| `spec-confirmed.json` | `confirmed`, `spec_version`, `confirmed_at` | engineer：`confirmed===true` 且 version 与 Spec 一致 |
| `test-report/summary.json` | `verdict`, `spec_version` | integrator：`verdict===pass`；tester：`spec_version` 与 Spec · `meta.version` 一致 |
| `RCA.json` | §2.6 全表 | Master 读 `restart_from` |
| `engineer-report.json` | （可选）`pytest_exit_code`, `tools_implemented[]` | — |

**assess-report.json（最小示例 · httpbin healthy）**：

```json
{
  "server_name": "httpbin",
  "registration": {
    "platform_registry": "present",
    "platform_registry_path": "/abs/.../platform-mcp-servers.yaml",
    "master_mcp_servers": "empty_expected"
  },
  "artifact_tree": {
    "forge_spec": true,
    "spec_confirmed": true,
    "repo": true,
    "test_report": true,
    "integration_pack": false
  },
  "health": {
    "pytest": "pass",
    "test_report_verdict": "pass"
  },
  "restart_from": "none",
  "summary": "代码与测试健康；platform registry 已含 httpbin；master mcp_servers 空为预期。",
  "evidence": ["/abs/.../FORGE-SPEC.yaml", "/abs/.../platform-mcp-servers.yaml"]
}
```

**RCA.json（最小示例）**：

```json
{
  "server_name": "httpbin",
  "failed_task_id": "t_abc123",
  "failed_step": "tester",
  "root_cause_layer": "engineer",
  "summary": "tool 名与 FORGE-SPEC 不一致",
  "restart_from": "engineer",
  "evidence": [
    "/abs/.../test-report/summary.json",
    "/abs/.../repo/src/httpbin_mcp/server.py"
  ],
  "escalate": false
}
```

**block metadata 公共字段**（执行链）：`forge_step`, `failed_step`, `block_reason`, `summary`, `evidence_paths[]`；需用户时加 `questions_for_user[]`。

**complete metadata 公共字段**：`forge_step`, `summary`；文件型加 `artifact_path`；integrator 加 `registered_tools[]`, `gateway_restart_required`。
