## 1. 需求

### 1.1 一句话

> **对任意 slug，在 Lab（`skstudio`）与 Production（`cli`）两侧用同一套四层漏斗（Catalog → 规划 → 已选 → 就绪）展示 Tool 消费状态；L1 机检覆盖 env + schema 注册；Lab 与发布链路 UI 可解释、可行动（sync-runtime）。**

**闭环动机**：仅 Lab 就绪无法保证 **publish-preflight / promote 后 worker 有 domain tool**（[能力与过程 §3.4](./能力与过程.md#34-部署) · 附录 G.2）。一期须把 Production 纳入同一 funnel API 与 validate，否则 agent 生命周期在「发布就绪」处断档。

### 1.2 对齐 [能力与过程 §2](./能力与过程.md#二智能体消费-tool)

| §2 能力 | 一期目标 | 现网基础 |
| --- | --- | --- |
| **2.1 列表** | `GET runtime/tools` 返回 funnel ①–④ + 明细 checks | readiness 仅有扁平 checks |
| **2.2 选择** | Builder：Lab overlay · 测评群：**release @ver** production overlay（双向 PATCH） | **现网** save 语义 · **一期** UI 写 API |
| **2.3 配置** | 两处 Tool 区块改 provider · 各自 sync-runtime | T0 + **一期** PATCH + sync |
| **2.4 Lab + Production** | Lab `skstudio` + Production `cli` 全链路（readiness / tools / sync-runtime） | Lab T0；Production ensure **现网**、validate **一期** |
| **2.5 API** | 读 `GET runtime/tools` · 写 `PATCH tool-overlay` + sync-runtime | readiness **现网** |

### 1.4 四层漏斗（一期必须对齐 · Lab + Production）

```text
① Catalog     ← CONFIGURABLE_TOOLSETS + TOOL_CATEGORIES（不读 YAML）
② Planned     ← infer_required_toolsets(SOUL, CHARTER)  与 BD-12 同源
③ Selected    ← merged config + overlay（Lab：`config.overlay` · Production：`config.production.overlay` / `platform_toolsets.cli`）
④ Ready       ← env.toolset.* + runtime.registered.*（staging 模式见 §2.5.1 · 不含 schema blocking）
```

**Normative · ② 真源**：复用 `agent_lab_impl_coherence.infer_required_toolsets`；**禁止**新建平行推断器。

## 2. 技术设计

### 2.1 架构

```text
Git overlay (③ selected · Lab + production overlay)
       ↓ materialize / merge / promote
lab profile (skstudio)          production profile (cli)
       ↓                              ↓
profile_tool_runtime  ──→  env checks (T0) + validate (T1)
       ↓                              ↓
build_runtime_tools_report(platform=skstudio|cli)
       ↓
GET .../runtime/tools + GET .../runtime/readiness?platform=
POST .../profile/sync-runtime  |  POST .../production/sync-runtime
       ↓
skstudio agent_lab_http 代理
       ↓
BuilderStudioPanel
  ├─ 总览（含 Tool 就绪一行）
  ├─ Tool（独立区块 · 列表/选择/配置）
  └─ 资产 / Gateway
       ↓
LabEvaluationPanel（总览 Production Tool 行 + **Production Tool 区块** · 绑 release @ver）
       ↓
publish-preflight PUB-tool-*
```

**原则**（[能力与过程 附录 G](./能力与过程.md#附录-g--实现约束与已知缺口normative--工程向)）：

- Hermes 单真源；skstudio **不**缓存 overlay
- 校验读 **profile `.env` 文件**，与 `_toolset_has_keys(os.environ)` 分离
- **禁止** slug 硬编码

#### 2.3.1 `materialize_release_staging`（normative · PR-4 核心）

**目的**：promote 前 **Git `@ver` → staging profile** 的单真源 materialize，供以下 **三处共用**（禁止各写一份 copytree）：

| 调用方 | 用途 |
| --- | --- |
| `GET …/runtime/tools?platform=cli&version=` | 测评群 Production Tool 区块读 funnel |
| `POST …/production/sync-runtime` · Body `version` | staging ensure env |
| `validate_publish_preflight` · `pub.tool.env` | 发布门禁 |

**Normative · 签名与行为**（`agent_lab_config.py` 或 thin wrapper）：

```python
def materialize_release_staging(slug: str, version: str) -> Path:
    """Git versions/<ver>/ → tmp staging dir; merge_production_config_overlay + ensure tool env from master (cli).
    与 promote 前 D62 materialize 同源；**不**写 profiles/<slug>/ 现网树。"""
```

- **缓存**：同一 `(slug, version)` 请求内可 memoize；**不**跨请求持久化 staging（每次 preflight 可重建）
- **并发**：Git commit 与 materialize 竞态时返回 **409** `staging_stale`
- **单测**：`test_materialize_release_staging_shared_by_tools_preflight_sync`（三入口同一 staging 内容）

<a id="24-api"></a>

### 2.4 API

Integration 前缀：`/integrations/skstudio/v1/agent-lab`（与 [规范 §9](../../platform_docs/专业智能体规范.md#9-agent-lab-工具共用契约) 一致）。

#### `GET /agents/{slug}/runtime/tools`（新增）

**Query**：`platform=skstudio`（默认 · Lab `profiles/lab-<slug>/`）| `platform=cli`（Production）

| Query | 含义 |
| --- | --- |
| `platform=skstudio` | **无 `version`**：读 **Lab profile** `profiles/lab-<slug>/`（测评群运维 / 兼容）；**Builder 必须带 `version`** |
| `platform=skstudio` + `version` | 读 Git `agents/<slug>/versions/<ver>/`（**Builder 真源**）；响应含 `"source": "git"`、`"staging": true`（env 计分 · schema 不参与） |
| `platform=cli` | 读 **Production**；见下 `version` |
| `version`（可选） | Git `@ver`；**Builder Lab Tool 必填**（= 版本下拉 @ver）；**测评群 Production 区块** = **`release_candidate_version`**（**策略 A：与 editing 同号**）。`platform=cli` 时 Hermes **materialize staging** 后组装 funnel |
| （无 `version` 且 `platform=cli`） | 读现网 **`profiles/<slug>/`**；未 promote 时 **404** `profile_not_found` |

**Normative · profile / staging 路径**：

| platform | 数据源 | `_get_platform_tools` 键 |
| --- | --- | --- |
| `skstudio` + `version` | Git `versions/<ver>/` · **`config.overlay.md`**（**Builder**） | `platform_toolsets.skstudio` |
| `skstudio`（无 version） | `profiles/lab-<slug>/` | `platform_toolsets.skstudio` |
| `cli` + `version` | Git `versions/<ver>/` → materialize staging · **`config.production.overlay.md`** | `platform_toolsets.cli` |
| `cli`（无 version） | `profiles/<slug>/` | `platform_toolsets.cli` |

**Normative · `staging` 与 overlay 文件（v1.6.1）**：响应字段 `"staging": true` **仅**表示 ready 计分 **不含 schema**（§2.5.1）。**不得**因此改读 `config.production.overlay.md`。`platform=skstudio` 始终读 **`config.overlay.md`**；`platform=cli` 读 **`config.production.overlay.md`**（或 materialize 后的合并结果）。

404 规则：Lab profile 缺失 · Production 无 `version` 且 `profiles/<slug>/` 不存在 → `profile_not_found`（UI 须可解释：测评群无预发布 @ver 时 Tool 区块 disabled）。

**Response 200**：

```json
{
  "slug": "reader",
  "platform": "skstudio",
  "funnel": {
    "catalog": [
      {"id": "web", "kind": "builtin", "label": "Web Search & Extract", "default_allow": true}
    ],
    "planned": ["web", "file", "skills"],
    "selected": ["web", "file", "skills", "hermes-cli", "memory", "terminal"],
    "ready": [
      {"id": "web", "ok": false, "checks": ["env.toolset.web"]},
      {"id": "file", "ok": true, "checks": []}
    ]
  },
  "items": [
    {
      "id": "web",
      "kind": "builtin",
      "provider": "firecrawl",
      "env_keys": ["FIRECRAWL_API_KEY"],
      "env_ok": false,
      "schema_tools": ["web_search"],
      "schema_ok": null
    }
  ],
  "checks": []
}
```

**Response 字段（staging）**：当 `platform=cli` 且带 `version` 时，响应 **必须** 含 `"staging": true`（供 `deriveToolReadySummary(..., { mode: "staging" })`）。

**字段规则**：

| 字段 | 来源 |
| --- | --- |
| `funnel.catalog[]` | `CONFIGURABLE_TOOLSETS` + `TOOL_CATEGORIES`；`default_allow` 一期恒 `true`（T3 读 YAML） |
| `funnel.planned[]` | `infer_required_toolsets(soul, charter)` sorted |
| `funnel.selected[]` | `_get_platform_tools(config, platform)` |
| `funnel.ready[]` | live：env ∧ schema（若 probe）；**staging**（§2.5.1）：**仅 env** |
| `items[].schema_ok` | `null` = 未配置映射；`true/false` = 已 probe |

**Errors**：`404 profile_not_found`（同 readiness）

#### `GET /agents/{slug}/runtime/readiness`（扩展）

**Query**：`platform=skstudio`（默认）| `platform=cli`

- **Lab**：现有 `validate_lab_runtime` + 追加 `validate_profile_tool_runtime` / `runtime.registered.*`（T1）
- **Production**：**新增** `validate_production_runtime(profile_dir, slug=)` — 仅 tool 相关 checks（`env.toolset.*`、`mcp.*.env`、`runtime.registered.*`）；**不含** Lab 专属项（`env.ws_url` 等）
- **Query `version`**：**一期不支持** readiness 带 `version`；预发布 Production 就绪读 **`GET runtime/tools?platform=cli&version=`**（§2.5.1），**不**扩 readiness staging
- `build_runtime_tools_report` **不替代** readiness；readiness 仍为 handoff / 发布就绪门禁真源

#### `POST /agents/{slug}/production/sync-runtime`（新增）

镜像 Lab `POST .../profile/sync-runtime`：

```json
{
  "restart_gateway": false,
  "version": "v0.7.1"
}
```

**Normative**：

| 场景 | 行为 |
| --- | --- |
| **无 `version`**（或已 promote） | 目标 `profiles/<slug>/`；`ensure_profile_tool_env_from_master(..., "cli")` + 可选 `ensure_inference_from_master`；**不** restart Lab gateway |
| **有 `version`**（预发布 · 测评群） | 对 Git `@ver` **materialize staging** 跑 ensure（与 preflight 同源）；刷新 `pub.tool.*` / funnel；**不**写 Lab profile |
| Response | `{ "readiness": validate_production_runtime(...).to_dict(), "profile": "..." \| "staging", "keys_merged": ["FIRECRAWL_API_KEY", ...] }`（**v1.5.1** · 仅 key 名不含值） |
| worker reload | 一期 **文档化**「promote 后 dispatch 新 spawn 读 profile `.env`」；不要求 gateway restart API |

#### 既有 `POST .../profile/sync-runtime`

- 行为不变；一期文档强调 `{ "restart_gateway": true }` 为 **默认推荐**（前端一键）
- **`restart_gateway: true`** 前先 **`ensure_gateway_service(slug)`**（install launchd/systemd 若缺 → start）

#### `POST /agents/{slug}/gateway/ensure-service`（**v1.5.2** · 通用机制）

**用途**：凡 **测评群**（`lab-<slug>`）与 **Agent Builder** Gateway，**必须**以 launchd/systemd **service** 运行；禁止长期依赖手动 `gateway run` 后再调 `--system restart`（macOS dev 会 180s 超时断 WSS）。

**Normative**：

| 触发点 | 行为 |
| --- | --- |
| 研发 **approve 阶段 B** | materialize 后 `ensure_gateway_service`（替代裸 install+start） |
| **`POST .../materialize`** | 成功后对 professional slug 自动 ensure（响应 `gateway_service` 字段） |
| **`POST .../gateway/start`** / **`restart`** | 先 ensure（缺 service 则 install）再 start/restart |
| **`POST .../profile/sync-runtime`** · `restart_gateway: true` | ensure → restart |
| 内置专家 `master/intel/coder/office` | **skip**（非 Lab profile） |

**CLI 等价**：`hermes -p lab-<slug> gateway install --system && hermes -p lab-<slug> gateway start --system`

**Failure**：restart 超时 → **503**（非 500）；侧栏文案指向 ensure-service 或手动 install。

#### `PATCH /agents/{slug}/tool-overlay`（新增 · UI 写回）

**用途**：Tool 区块 **选择 / 配置（provider）** 的双向写回；**不**替代整包 `lab_version_save` 定版，但 **同语义** 更新 overlay。

**Body**（示例 · Builder Lab）：

```json
{
  "version": "v0.3.0",
  "context": "builder",
  "toolsets_enabled": ["web", "file", "skills"],
  "toolsets_disabled": ["terminal"],
  "providers": { "web": { "backend": "firecrawl" } }
}
```

**Body**（示例 · 测评群 Production · `version` = **`release_candidate_version`**）：

```json
{
  "version": "v0.7.1",
  "context": "lab_evaluation",
  "toolsets_enabled": ["web", "file", "skills", "kanban"],
  "toolsets_disabled": [],
  "providers": { "web": { "backend": "firecrawl" } }
}
```

**Normative · 服务端（v1.9.0 · 双 overlay 各自读写）**：

1. 目标 = Body **`version`** 对应 Git 工作区（Builder = **版本下拉 @ver**；测评群 = **`release_candidate_version`**，须与 registry 一致否则 **409**）
2. **Tool PATCH 只写当前 context 对应 overlay**；**不**调用 `ensure_config_overlay_sync` / `ensure_production_overlay_sync`（parity merge 仅 **`ensure_impl_bundle` / `lab_version_save`** 路径，见 PR-C）
3. **`context=builder`**：仅写 **`config.overlay.md` / `platform_toolsets.skstudio`**；commit 前 **BD-12** blocking（SOUL/CHARTER 必需 tool ⊆ Lab overlay）
4. **`context=lab_evaluation`**：仅写 **`config.production.overlay.md` / `platform_toolsets.cli`**；commit 前 **BD-12b** blocking（SOUL/CHARTER 必需 domain tool ⊆ Production overlay）
5. **Lab 与 Production tool 集合允许不一致**；kanban 等 Production 专属项仅在 Production Radio 配置
6. **禁止**写 `files_json` 手改 SOUL/CHARTER；**禁止** skstudio 本地缓存真源
7. 成功 → git commit（message `tool-overlay: …`）；无 staged 变更 → **200** + `overlay_updated: false`（幂等）；失败 → 见下表
8. 与 [Builder 410 白名单](../../cservice/docs/builder需求与实现.md#42-http-apibuilder-群) 关系：**窄域写例外**，**非** `spec/apply` 全量

**Normative · 版本门禁（Builder）**：

| 条件 | PATCH |
| --- | --- |
| Body `version` ∉ `list_versions(slug)` | **404** `version_not_found` |
| 其它 slug 树 dirty 文件 | **不**预检；窄域 commit 仅 `agents/<slug>/versions/<ver>/` |

**Normative · 版本门禁（测评群）**：

| 条件 | PATCH |
| --- | --- |
| 无 `release_candidate_version` | UI **disabled**；API **409** `release_version_required` |
| `release_stale` | 提示重新预发布；可 PATCH 但 preflight 可能 stale |
| `git_tree_clean === false` | **409** `git_dirty`（与预发布/发布门禁一致） |

**Normative · 错误码（PATCH）**：

| HTTP | code / check | 含义 |
| --- | --- | --- |
| 409 | `release_version_required` | 测评群 · 无 `release_candidate_version` |
| 409 | `release_version_mismatch` | Body `version` ≠ registry `release_candidate_version` · 响应含 `requested_version` / `release_candidate_version` |
| 409 | `git_dirty` | **`context=lab_evaluation` 专用** · Git 树未 clean |
| 422 | `git_commit_failed` | Builder 窄域 commit 失败（hook / git 错误） |
| 409 | `staging_stale` | materialize 与 Git HEAD 不一致 |
| 422 | `bd12_blocked` | **builder** · Lab overlay 缺 SOUL/CHARTER 必需 tool |
| 422 | `bd12b_blocked` | **lab_evaluation** · Production overlay 缺 SOUL/CHARTER 必需 domain tool |
| 409 | `overlay_conflict` | 乐观锁 / `version` 与 working tree 目标不一致（若启用 ETag） |

**Normative · Git commit**：成功路径 **必须** `git commit`（message `tool-overlay: …`）；pre-commit hook 失败 → **422** + 错误明细，**不** partial 写 overlay；UI 提示用户修复后重试（**不** amend 自动重试）。

**Normative · 不写经 UI 的项**：

| 项 | 原因 | UI 行为 |
| --- | --- | --- |
| `*_API_KEY` 等 secrets | 审批人 · `profiles/master/.env` | 显示缺 key + 指引 |
| 未 catalog 登记 MCP | T3 前人工 | 409 / inline 错误 |
| `lab-<slug>` profile `.env` | runtime 层 | Builder：**不**做 profile sync-runtime；handoff 后测评群 sync |
| `profiles/<slug>/` `.env` | runtime 层 | 测评群：**production sync-runtime**（可带 `version`） |

**Response 200**：`{ "overlay_updated": true, "validate": { … BD-12 … }, "runtime_tools": { … } }`（可选 inline 刷新 funnel）

#### 2.5.1 Staging 模式（`platform=cli` + `version` · normative）

**适用**：测评群 Production Tool 区块 · publish-preflight **`pub.tool.env`** · `production/sync-runtime` 带 `version`。

| 项 | live profile（Lab / 已 promote cli） | staging（Git `@ver` materialize） |
| --- | --- | --- |
| `env.toolset.*` / `pub.tool.env` | **blocking** | **blocking** |
| `items[].schema_ok` | probe · 参与 ready | 恒 **`null`** · UI 显示 **`—`** |
| `runtime.registered.*` / `pub.tool.registered.*` | **error** · 参与 ready（live） | **不生成 / 不参与 preflight**（无 running worker） |
| `deriveToolReadySummary` | env ∧ schema | **仅 env**（§2.8.6 `mode: staging`） |

**Normative**：预发布阶段 Production Tool 行与 publish-preflight **不得** 因 schema 未 probe 而恒红；promote 后 `GET …/tools?platform=cli`（无 `version`）再启用 schema / `runtime.registered.*` blocking。

#### 2.5.2 publish-preflight tool 块（一期 · 生命周期闭环）

**目标**：`phase=publish-preflight` 在现有 PUB-1～PUB-4b 之外，**blocking** 校验 **staging production profile** 的 tool **env** L1。

**Normative**：

| check id | 条件 | staging preflight | promote 后 live |
| --- | --- | --- | --- |
| `pub.tool.env` | staging 上 `validate_profile_tool_runtime(..., "cli")` 任一 **env** error | **blocking** | 同左（若 re-validate） |
| `pub.tool.registered.<name>` | `runtime.registered.*` error | **不生成**（§2.5.1） | 可选 **warning**（`ok:null`）一期；T2 可升 blocking |

- 校验对象：Git `@ver` · **`materialize_release_staging`**（与 `GET runtime/tools?platform=cli&version=` 同源）

- **Production Tool 总览行**（§2.8.4.2）= **`deriveToolReadySummary`**，**非**全量 `publish_preflight.checks` 计数
- skstudio **LabEvaluationPanel**：Tool 区块内可行动（PATCH + production sync）；`<details>` 可展示 **`pub.tool.*` 明细**（与总览行分工）

##### 2.8.4.5 预发布 pin 与 stale（normative · v1.7.0 · supersede §2.8.4.5 双 semver fork）

| 场景 | Builder（Lab Tool） | 测评群（Production Tool） |

#### 2.8.6 文案与类型（`agentLabUi.ts` / `agentLabTypes.ts`）

**`RuntimeToolsReport`**、**`deriveToolReadySummary(report, opts?) → { ok, ready, total, mode }`**（Builder + 测评群 **唯一** 摘要函数）。

**Normative · `deriveToolReadySummary` 计分**：

| 字段 | 规则 |
| --- | --- |
| **分母 `total`** | `funnel.ready.length`（= 对 **`planned ∩ selected`** 中需 L1 机检的项；**不含** 仅 scaffold 且不在 planned 的 `hermes-cli` / `memory`） |
| **分子 `ready`** | `funnel.ready` 中 `ok === true` 计数 |
| **`ok`（总览 是/否）** | `ready === total && total > 0`；`total === 0` → `—` |
| **`mode: "staging"`** | cli + `version` 或 report 含 `staging: true` → ready 判定 **仅 env**（§2.5.1）；schema / `runtime.registered.*` **不参与** |
| **`mode: "live"`** | Lab profile 或已 promote cli → env ∧ schema（若 `schema_ok` 非 null） |

**禁止**：总览行与 Tool 区块各写一套计分；禁止测评群用 `publish_progress` 代替 Production Tool 行。

**`runtimeCheckLabel` 扩展**（Vitest 必覆盖）：`env.toolset.*`、`runtime.registered.*`、`pub.tool.*` 等。

**T3 扩展**：catalog admin UI · MCP 登记 · `tool.not_in_catalog` blocking UI。

#### 2.8.7 交互流（reader · 双向 · Lab + Production）

```text
Builder / 测评群（Lab Radio）：勾选 web → [应用更改] → PATCH platform=skstudio → Lab Tool 行刷新 · commit hash 反馈

测评群（Production Radio · 已预发布）：确认 kanban + web → PATCH platform=cli → Production 行 + pub.tool.* 刷新

测评群（Lab Radio）：overlay 已应用 · env 红 → [同步 lab tool env] → @Bot 对话可用 key
```

#### Troubleshooting：Lab 绿 / Production 红

| 现象 | 原因 | 修复 |
| --- | --- | --- |
| Builder **Lab Tool 是**，测评群 **Production Tool 否** | Lab 读 `profiles/lab-<slug>/`（skstudio）；Production 读 Git `@release` 的 **staging cli** profile，**env 相互独立** | 审批人在 `profiles/master/.env` 配 key → 测评群 Production Tool 区块点 **「同步 production tool env」** |
