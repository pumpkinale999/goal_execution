## 1. 需求

### 1.1 一句话

> **以四中心（Tool · Skill · Model · Slug）组织平台能力：前三个中心维护全 slug 可选用的供给池（浏览、登记、secrets、缺省 model）；Slug 中心配置各业务 agent 如何选用并对齐 Lab/Production 就绪——统一侧栏入口，复用一期 Tool 消费组件，逐步补齐 Skill/Model 与 catalog 硬门禁。**

### 1.2 产品模型（normative）

```text
  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐
  │  Tool 中心   │  │  Skill 中心  │  │  Model 中心  │   供给层（租户/平台）
  └──────┬───────┘  └──────┬───────┘  └──────┬───────┘
         └─────────────────┼─────────────────┘
                           ▼
                  ┌─────────────────┐
                  │    Slug 中心     │           消费层（per 自定义 slug）
                  └─────────────────┘
                           ↓
              Git @ver  →  lab-<slug> / <slug>
```

| 层 | 回答的问题 | 典型操作 |
| --- | --- | --- |
| **Tool / Skill / Model** | 全站有什么？密钥/注册是否就绪？ | Tool/MCP 登记 · Model 配 key · Skill **只读 list** |
| **Slug** | 这个 agent 选用哪些？Lab/Production 能否跑通？ | **只读浏览** Tool 选用 · **skill select/deselect** · Apply → Git |

**Normative · 配置分工**：

| 配置类型 | 归属 | 落盘 |
| --- | --- | --- |
| **Secrets**（API key 等） | Tool / Model 中心（admin） | `profiles/master/.env` → sync-runtime |
| **Provider 选择**（如 `web.backend: firecrawl`） | Slug 中心（创建者） | Git `config.overlay.md` / production overlay |
| **Tool/Skill 选用** | Slug 中心 | Git overlay · `skills.lock.yaml` |
| **缺省 model** | Model 中心（**SPA 只读**）· 主 model **徽标** · 变更走运维/脚本 | master `config.yaml`（`PATCH .../models/default` 保留 API） |

### 1.6 四层漏斗（Tool · Slug 共用）

```text
① Catalog     ← Tool/MCP catalog · Model provider · Skill 内置路径 + Git 扫描（**无** skill 注册表）
② Planned     ← Slug 中心（BD-12 推断 · SOUL/CHARTER）— **仅 Tool**
③ Selected    ← Slug 中心（overlay · skills.lock）
④ Ready       ← 供给 secrets + Slug 选用 + sync-runtime + schema
```

Skill / Model **复用 ①③④ 子集**（无 BD-12 式 planned）；Skill ④ = 文件可访问 + lock 有效；Model ④ = `ensure_inference_from_master` 满足。

### 1.7 角色与权限（normative）

**审批人** = `SKSTUDIO_GROUP_CREATION_REVIEWERS`（与建群/发布共用，[建群审批](./skstudio-建群审批-需求与设计.md)）。

**slug 创建者** = **当前登录用户**，且同时满足：

1. **`agent_registry.owner_user_id = current_user.id`**（该 slug 登记在其名下）  
2. 该用户为其 **Agent Builder 教练群** 的 **群 owner**（`conversation.created_by_user_id` · `thread.agent_slug = agent-builder` · 一人一 coach 群）

**Normative · 产品语义**：创建者打开管理中心时，**就是**自己的 Builder 教练群 owner；可管理的 slug 列表 = **本人拥有的业务 slug**（与 Builder 右栏 `coaching_targets` 同源）。**admin** 视同全部 slug 创建者。

**Normative · 三期 ACL 范围**：**仅**「slug 创建者（= 上述 owner 用户）+ admin」；**不含** Builder 群普通成员、协作者。fork 后新 slug 绑定新 `owner_user_id`。

| 操作 | slug 创建者 | admin |
| --- | --- | --- |
| Tool/Skill/Model 中心 · 浏览 | ✅ | ✅ |
| 供给 · 增删登记 / 配 secrets / 缺省 model | ❌ | ✅（**仅 Tool/Model**；Skill **无** 供给登记） |
| Slug · **select / deselect** Skill | ✅ 自己的 slug | ✅ |
| Slug · sync-runtime | ✅ 自己的 slug | ✅ |
| 内置 Tool/Skill · **卸载 UI** | ❌ | ❌ |
| Skill **上传 / 登记 / 删除** | ❌ | ❌（skill 文件由 Builder save / Git 维护） |

### 1.8 非目标（三期明确不做）

- master / builder / 内置 profile 的管理 UI
- Forge 编排与 Kanban 改造（见 [二期](./能力与过程(二期).md)）
- Skill 过程层全文（[过程与技能.md](./过程与技能.md) 待写）；三期只做 **list + skills.lock select/deselect**
- 推理 env 与 tool env **双轨合并**（仍并存）
- 多租户隔离（单租户 MVP；catalog/env 全局）
- Builder 右栏 **移除** Tool 区块（三期 **并存**，管理中心为第二入口）

### 1.9 分期里程碑（产品）

| 里程碑 | 范围 |
| --- | --- |
| **M1** | 管理中心壳 · Tool 中心只读 · Slug 聚合（复用一期 Tool UI） |
| **M2** | Tool 中心 MCP 登记 UI · Model 中心 · admin secrets 表单 |
| **M3** | Skill **列表**（只读）· Slug **select/deselect** · `skills-lock` PATCH |
| **M4** | `tool.not_in_catalog` blocking · 卸载引用扫描 · funnel check 中文文案 |

**M1 独立发布理由（normative）**：

1. **统一 slug 列表** — 创建者不必进 Builder 即可查看可管理 slug 与 Tool 就绪摘要  
2. **供给只读诊断** — Tool 中心展示 builtin/MCP catalog + env 就绪（无 key 明文），便于创建者与 admin 对齐「缺 key vs 未选用」  
3. **只读 Slug Tools** — 管理中心展示当前 @ver 已启用 tool（内置 + MCP 两表），样式对齐 Tool 中心；**不**嵌入可编辑 `AgentLabToolSection`  
4. **与 Builder 并存** — M1 **不**替代 Builder/测评群；作为第二入口，L1 对称性纳入 DoD

## 2. 技术设计

### 2.1 架构

```text
[管理中心 UI · skstudio 侧栏]
  ├── Tool 中心 ──────► GET/PATCH catalog · POST master-env (admin)
  ├── Skill 中心 ─────► GET skills（只读 list · M3）
  ├── Model 中心 ─────► GET/PATCH model-providers (M2)
  └── Slug 中心 ──────► 复用一期 agent-lab API
         │
         ▼
skstudio backend（鉴权 · 审批人门禁 · 代理）
         │
         ▼
Hermes integration API  +  `/integrations/skstudio/v1/admin/center/*` (M1+)
         │
         ├── {HERMES_SHARED_ROOT}/platform-tool-catalog.yaml（M2 起 runtime 真源）
         ├── profiles/master/.env
         ├── agent-lab-git/agents/<slug>/versions/<ver>/
         └── profiles/lab-<slug>/ · profiles/<slug>/
```

**原则**（延续 [一期 §2.1](./能力与过程(一期).md#21-架构)）：

- Hermes **单真源**；skstudio **不**缓存 overlay / catalog
- Slug 选用变更 **必须** Git commit（`lab_version_save` / 窄域 commit）
- **禁止** slug 硬编码；**禁止**管理中心双写 registry

### 2.2 真源表（normative）

| 资产 | 真源 | 三期写入口 |
| --- | --- | --- |
| Tool catalog（内置） | Hermes `CONFIGURABLE_TOOLSETS` | 只读 |
| Tool catalog（MCP） | **`{HERMES_SHARED_ROOT}/platform-tool-catalog.yaml`**（normative · M2 起） | Tool 中心（admin）· Hermes `platform_tool_catalog.py` |
| Tool catalog（seed） | [docs/platform-tool-catalog.yaml](./platform-tool-catalog.yaml) | 部署/bootstrap **复制**至共享根；**非** runtime 直读 docs 路径 |
| Tool secrets | `profiles/master/.env` | Tool / Model 中心（§2.12） |
| Tool 选用 | Git overlay | Slug 中心（一期 agent-lab API） |
| Skill 注册表 | **无独立注册表** | — |
| Skill **可发现集合** | Hermes 内置 skill 路径 + Git `versions/<ver>/skills/`（只读扫描） | Skill 中心 **list** |
| Skill **选用** | Git `skills.lock.yaml` | Slug 中心 **select / deselect** |
| Model / 推理 env | master `.env` | Model 中心（§2.12） |
| Runtime | materialize / promote | 非 UI 手改 |

### 2.3 Tool 中心（方案 B · registry）

#### 分区

| Section | 真源 | 行为 |
| --- | --- | --- |
| **内置 Tool** | `{HERMES_SHARED_ROOT}/platform-tool-catalog.yaml`（**仅** `kind: builtin`） | 只读列表 + env 诊断 |
| **平台 MCP** | `{HERMES_SHARED_ROOT}/platform-mcp-servers.yaml` | 只读扫描（Forge integrator 写入）；**无**「登记 MCP」按钮 |

#### Slug 选用 MCP

- overlay **`mcp_enabled: [server_id]`**（仅 id）
- `sync-runtime` / materialize 从 registry 展开到 profile `config.yaml` · `mcp_servers`
- Slug 页 **双按钮**：「添加内置 Tool」「添加 MCP Tool」

#### API（M2+）

| 路由 | 行为 |
| --- | --- |
| `GET .../tools` | `{ builtin[], mcp_servers[], catalog_etag, registry_etag }` |
| `GET .../mcp-inventory` | registry 条目 + tools 缓存 + env_ok + 引用 slug 数 |
| `POST/PATCH .../tools/mcp` | **410**（catalog 登记已废弃） |
| `PATCH .../master-env` | admin secrets（不变） |

**校验**：spec-ready · `tool.mcp_not_in_registry`（overlay 引用 id ∈ registry active）。

#### Provider 不在 Tool 中心

`web.backend` 等 **provider 选择** 仅在 **Slug 中心** 写 overlay（[一期 PATCH tool-overlay](./能力与过程(一期).md#24-api)）。

### 2.4 Skill 中心（list · 只读）

**Normative · 范围**：Skill **只有 list、select、deselect** 三个产品动作；**不做**上传、登记、registry、tarball、admin 增删 skill 包。

| 动作 | 中心 | 说明 |
| --- | --- | --- |
| **list** | Skill 中心 | 浏览可用 skill；分 **内置** / **Git 已存在**（`skills/` 目录） |
| **select** | Slug 中心 | 勾选 → 写入 `skills.lock.yaml` |
| **deselect** | Slug 中心 | 取消勾选 → 更新 `skills.lock.yaml` |

#### list · 数据来源（normative）

| 分类 | 来源 | 谁增加 skill 文件 |
| --- | --- | --- |
| **内置** | Hermes / 平台已安装 skill 路径（只读扫描） | 发版 / 运维 |
| **Git 已存在** | 某 slug `agent-lab-git/.../versions/<ver>/skills/**` | **Builder save** / Git（现网）· **非**管理中心 UI |

Skill 中心 **只读展示**；**不**提供上传或登记入口。新建 skill 内容仍在 **Builder 群** 对话 save 进 Git。

**Normative · `GET .../skills` Git 扫描范围**：

| 调用方 | 无 `slug`/`version` query | 指定 `slug` + `version` |
| --- | --- | --- |
| **admin** | 扫描 **全部**业务 slug · 各 slug 取 registry **`current_editing_version`** 下 `skills/` | 指定 `@ver` 目录 |
| **创建者** | 仅 **`owner_user_id = self`** 的业务 slug · 同上取 editing `@ver` | 须 slug owner · 指定 `@ver` |
| **builtin** | 始终全平台 Hermes 内置路径扫描 · 与 query 无关 | 同左 |

Skill 中心 list = builtin ∪ Git 扫描并集（去重 `id`）；Slug › Skills 页另按 [可选集合](#skill-selectable-set) 过滤。

#### M1–M2

- Skill Tab **hidden/disabled** 或占位「M3」
- Slug 内 skill 仍由 Builder `lab_version_save` / `ensure_impl_bundle` 维护 lock

#### M3 · UI + API

| 能力 | 行为 |
| --- | --- |
| **GET .../admin/center/skills** | 返回扁平 **`items[]`**（`kind`: `builtin` \| `git` · 见 §2.8） |
| **Slug › Skills** | checkbox 见 [§2.4 可选集合](#skill-selectable-set)；Apply → **`PATCH .../skills-lock`** |

<a id="skill-selectable-set"></a>

**Normative · 可选集合（Slug › Skills）**：

| 条目类型 | Slug 页 checkbox | 说明 |
| --- | --- | --- |
| **`kind=git`** | 仅当该 slug `@ver` 下 `skills/<id>/` **目录存在** 时可勾选 | 新建 skill 须回 **Builder save**；Skill 中心 list 为全局可发现，Slug 页为 per-slug 子集 |
| **`kind=builtin`** | **`selectable: false`** · 只读展示 | 如 `kanban-worker` 由 **promote** 追加至 worker lock，UI 不可 deselect |
| **SOUL 仍引用** | deselect **阻断** | BD-13：`PATCH skills-lock` 返回 **409** + `blocking_skills[]`（§2.8） |

**Normative · select/deselect 落盘**：

- 仅改 `versions/<ver>/skills.lock.yaml` 的 **`include`**（现网格式 `version: 1` + `include: []`）；**不**改 `skills/**` 文件本体  
- **无** Lab/Production 双 overlay（与 Tool 不同）；lock 随 Git `@ver` 单写，promote 后 worker **同版** lock  
- 经 **`ensure_impl_bundle` / `check_skills_lock_coherence`** 校验 · narrow Git commit  
- **与 Builder save 交互**：`lab_version_save` 内 `ensure_skills_lock_sync` 会把 SOUL `skill_view` **加回** `include`；管理中心 **deselect** 若 SOUL 仍引用 → BD-13 **409**（须先改 SOUL 或保留勾选）· **不**在 save 后 silent 覆盖 UI 已 deselect 项（PATCH 路径 **不**调 `ensure_skills_lock_sync` 追加，仅校验 coherence）

详见 [附录 C · Skill list/select/deselect](#附录-c--skill-list--select--deselect)。

### 2.5 Model 中心（M2 · v1.2.1 UI）

### 2.12 master-env 与 secrets 安全（M2 · normative）

| 规则 | 说明 |
| --- | --- |
| **谁可读明文** | **仅** admin 通过 `PATCH .../master-env` 写入；**任何** GET 仅返回 `configured: true/false` 或 `masked: "***"` |
| **谁可写** | admin · 服务端写 `profiles/master/.env` · **禁止**前端/localStorage 缓存明文 |
| **审计** | 每条 PATCH 记 `actor_user_id`, `keys_updated[]`（**键名 only**）, `timestamp` |
| **响应** | `{ "keys_updated": [...], "keys_removed": [...], "keys_ignored": [] }` · **禁止** echo 值 |
| **sync 指引** | 响应含 `hint: "创建者须在 Slug 中心或测评群执行 sync-runtime"` |
| **keys_merged** | 仍仅在 **sync-runtime** 响应暴露键名列表（[一期](./能力与过程(一期).md)）；管理中心 master-env **不**返回 `keys_merged` |
| **日志** | structlog / audit **禁止**打印 env 值；pytest 断言日志无 `sk-` 等 key 模式 |

<a id="附录-c--skill-list--select--deselect"></a>

## 附录 C · Skill：list · select · deselect

### C.1 原则（normative）

| 做 | 不做 |
| --- | --- |
| **list** 可用 skill（内置 + Git 已有） | 上传 skill 包 |
| **select / deselect** → `skills.lock.yaml` | Skill registry / manifest |
| Builder save 写 `skills/**` 内容 | 管理中心编辑 `SKILL.md` |

### C.2 三动作

```text
Skill 中心（list）          Slug 中心（select / deselect）
  内置 skill 扫描    ──→      checkbox 勾选
  Git skills/ 扫描   ──→      PATCH skills-lock → include[]
```

### C.3 `skills.lock.yaml`（沿用现网）

由 `ensure_impl_bundle` 托管；UI **只**改 **`include`**（skill id 或相对 `skills/` 路径）。**deselect** = 从 `include` 移除项；**不**删除 Git 中 `skills/` 目录。

### C.4 与 Tool 中心对比

| | Tool | Skill |
| --- | --- | --- |
| 供给 list | catalog + MCP（M2 登记） | 内置扫描 + Git **只读** |
| 供给增删 | admin 登记 MCP | **无**（Git/Builder） |
| Slug 消费 | overlay toolsets | lock **include** |

### C.5 机检

- **BD-13**：SOUL `skill_view` 引用 ⊆ lock `include` · deselect 违反 → API **409**（§2.8）  
- **HD-7**：materialize 后 lock 中项在 profile 可读  

<a id="c6-与-tool-的差异--lock-版本"></a>

### C.6 与 Tool 的差异 · lock 版本

| 项 | Tool（Slug›Tools） | Skill（Slug›Skills） |
| --- | --- | --- |
| 落盘 | Lab / Production **双 overlay**（**编辑**在 Builder/Tester） | 单文件 `versions/<ver>/skills.lock.yaml` |
| UI Radio | Lab \| Production（**只读**切换 overlay 视图） | **无** · 仅 `@ver` 下拉 |
| 供给登记 | admin 登记 MCP（M2） | **无** · Git/Builder |

### C.7 范围外格式

`agent-builder` 等教练 profile 的 lock 可能非 `version: 1` + `include[]` 形状；三期 **不**纳入管理中心（§1.4）。

### C.8 与 `lab_version_save` 的分工

| 路径 | `ensure_skills_lock_sync` | BD-13 |
| --- | --- | --- |
| **Builder `lab_version_save`** | **会**把 SOUL 引用 **合并进** `include` | save 后机检 |
| **管理中心 `PATCH skills-lock`** | **不**追加 SOUL 引用 · 仅写客户端提交的 `include` | PATCH 前 **`check_skills_lock_coherence`** · 失败 **409** |

因此：欲 deselect 某 skill，须 **先**在 Builder 改 SOUL 去掉 `skill_view`，**再**于 Slug›Skills 取消勾选。
