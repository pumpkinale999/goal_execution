## 1. 问题与动机

现网 §3.3.8.1：**同一年度至多一条** active company 根。产品意图是「**一个规划年内多个顶层战略目标**」（period=年；年内多顶层 goals；子目标按季/月），与「每年一个顶层容器、多目标只能做 sub」不同。

应用层闸 `duplicate_active_year` 与按年 `.first()` / `copy_from_year` 假设阻塞该意图。

## 3. 规范要求（Normative）

### 3.1 产品模型

```text
同一 planning_year
  ├── Objective(company · name=A)     ← 顶层战略目标 1
  │     └── Objective(sub)* · period 季/月/年（⊆ 父年窗）
  │           └── Program* → Project*
  ├── Objective(company · name=B)     ← 顶层战略目标 2
  │     └── …
  └── …（该年全部状态合计 ≤ 10）
```

| 规则 | 说明 |
| ---- | ---- |
| **身份** | 顶层 = `level=company` · `is_default=false` · `YEAR(period_start)=planning_year` |
| **时间窗** | 新建根仍 `year_bounds(planning_year)`（`YYYY-01-01`～`YYYY-12-31`）；子节点 ⊆ 父 company 年窗（现网不变） |
| **考核** | 每个 company / sub / program **各自** `lifecycle_status`（§3.3.8.2） |
| **挂靠** | Program.`objective_id` / Project.`program_id` 仍单父；**禁止** 一 Program 服务两棵 company 树 |
| **owner** | `POST /years` 创建时 **`owner_user_id` = 当前调用用户**（actor / JWT uid）；**不**另开选人必填 |

### 3.2 数量与命名

| 规则 | 说明 |
| ---- | ---- |
| **数量上限** | 同 `planning_year` 下正式 company 根 **≤ 10**，计数 **含全部** `lifecycle_status`（`active` · `pending_assessment` · `met` / `partial_met` / `not_met` · `archived` 等）；超出 → **400** `annual_root_limit_exceeded` |
| **name 必填** | `POST /years` body **`name`** 必填；服务端 **trim** 后非空；长度 **1～200**（超出 → **400** `name_invalid` 或归入 `name_required`/`invalid_request`，实现选一并在 OpenAPI `maxLength: 200` 钉死）；缺省/空白 → **400** `name_required` |
| **同年重名** | 同 `planning_year` 下，任意正式 company 根（**含** 上述全部状态）**不得**与拟用 `name` 冲突（大小写敏感与现网 `name` 比较一致）；冲突 → **400** `duplicate_annual_name` |
| **废止** | **400** `duplicate_active_year`；旧草案码 `annual_active_limit_exceeded` **勿用**（改用 `annual_root_limit_exceeded`） |

**rename（PATCH）**：改 `name` 须通过同一「同年重名」校验。

### 3.3 API

#### 3.3.1 `POST /ge/objectives/years`

| 字段 | 约束 |
| ---- | ---- |
| `planning_year` | 必填 · INT · 日历年（现网） |
| `name` | **必填** · 正式顶层显示名 |
| `copy_from_objective_id` | 可选 · 源须为正式 company 根；复制其 Sub/Program 结构（及现网已复制字段）到新根下 |
| `copy_from_year` | **废弃**：一旦传入 → **400** `copy_from_year_deprecated`（**无** 单根年短兼容） |

**权限**：仍仅 **评审员**（经 BFF）。

**owner**：服务端写 **`owner_user_id` = actor_user_id**（当前用户）。

**成功**：返回新建 company Objective（含 `planning_year` 派生字段 · `owner_user_id`）。

#### 3.3.2 读序与根 reorder（修订 M32 · **IN**）

`GET /ge/objectives` / 组树读序：

1. `planning_year` **DESC**（年组顺序）
2. 同年内：`sort_order ASC, name ASC`

**手工 reorder（IN）**：

| 规则 | 说明 |
| ---- | ---- |
| **范围** | **仅** 同一 `planning_year` 的正式 company 根互为兄弟；**禁止** 跨年交换 |
| **实现注意** | 现网 `sibling_objectives(parent_id=None)` 会混入**所有年**根 — M38 **须**改为（或分流）「同年 company 根」集合后再 swap/`_normalize` |
| **读键** | `annual_root_sort_key` **须**含 `sort_order`（如 `(-year, sort_order, name)`），不能仅 `(-year, name)` |
| **生命周期** | 沿用 M32：仅 `lifecycle_status=active` 可 reorder；否则 **403** `strategic_locked` |
| **权限** | 与现网结构写一致（评审员 / 适用 governor） |
| **创建** | `sort_order = next`（可在同年根集合内 `max+10`，或沿用全局 `parent_id IS NULL` 的 next；读序以同年集合为准） |

#### 3.3.3 「默认公司战略根」/ 深链（≠ GA DQ 缺省根）

| 场景 | 行为 |
| ---- | ---- |
| URL / 信号已带 `objective_id`（或可解析到唯一祖先 company） | 用该根 · 树选中该节点 · 展开祖先年组 |
| 「进入当年战略 / 浏览执行力」**未** 指定根，且当年展示用根 **0** | 空态 / 引导新建 |
| 同上且 **恰好 1** 个合适根 | 可用该唯一根（仅为唯一解，**非**产品「默认战略」） |
| 同上且 **>1** · **浏览类**入口 | **展开该年组 · 不预选** 任一根；用户在组内点击 |
| 同上且 **>1** · 当前动作 **硬性需要** 单一 `objective_id`（如治理分发） | **轻量选根列表**（`name` + lifecycle 标签）→ 选定后再继续；**禁止** `.find`/`.first()` |

废止前端 `resolveActiveAnnualCompanyRootId`「当年 find 一条否则扫年」作为静默默认（多根时必须改行为）。

**Normative · 与 GA 分界**：本条只约束执行力/深链对 **公司顶层战略** 的选择。GA §21.3「缺省根」= maximal owned 评价锚点，**本迭代不改动**。

### 3.4 UI（执行力 · Accepted）

| 项 | 规则 |
| ---- | ---- |
| 入口 | 左树标题行 **「+ 新建年度战略」**（testid 可保留 `execution-create-year-link`） |
| 弹窗 | 规划年 + **名称（必填）** + 可选复制源顶层；**无** owner 选人 |
| 复制源 | 列表 = 具体顶层（`name` + 年 + lifecycle）；**不是** 仅年份 |
| **年组** | **可折叠**虚拟组头；组头文案 **仅年份**（如 `2026`）· **不** 显示条数；testid `execution-tree-year-group-{year}` |
| **组内节点** | 展示顶层 **`name`** + lifecycle 后缀；默认仅 active；「全部」勾选后同组含非 active |
| **根 ↑↓** | **仅** 详情页 **结构** Tab（与现网 sub 一致）；左树 **只读** 同步读序 · **禁止** 树内 ↑↓ / 拖拽 |
| **创建成功** | 关闭弹窗（或保持关闭）· **选中** 新建根 · **展开** 其所在年组 · 打开该根详情（与现网创建后深链习惯一致） |
| **多根未指定** | 见 §3.3.3：浏览展开年组不预选；硬性要根 → 选根列表 |
| 错误文案 | 见 §3.7 文案表 |

**选根列表（Normative · 硬性要根时）**：

- 标题建议：「选择战略目标」
- 行：`name` · 可选 lifecycle 标签 · 可选年（若列表跨年）
- testid 建议：`execution-pick-annual-root-modal` · `execution-pick-annual-root-{id}`
